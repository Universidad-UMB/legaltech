# NFR-001 — Requisitos no funcionales del primer incremento

| ID | Atributo | Requisito verificable | Evidencia requerida en desarrollo |
|---|---|---|---|
| RNF-01 | Seguridad | El **100%** de operaciones protegidas rechazan token ausente/inválido y aplican permisos por rol y recurso | Matriz de pruebas HTTP 401/403/404 para cada categoría |
| RNF-02 | Aislamiento | Ningún endpoint retorna datos de novedades/publicaciones de otro seguimiento no autorizado | Pruebas cruzadas A/B y A/A2, incluidas consultas por UUID |
| RNF-03 | Integridad | Duplicados de cambios y novedades se previenen bajo dos transacciones concurrentes | Tests PostgreSQL con conexiones independientes + conteo 1 |
| RNF-04 | Consistencia | Publicación no queda visible si falla el commit de estado+puntero+auditoría | Test de fallo inyectado y rollback posterior |
| RNF-05 | Trazabilidad | Todas las 18 pruebas `PROTO-AT` tienen prueba(s) automatizada(s) y evidencia de resultado | Matriz AT→test, reporte PASA/FALLA/BLOQUEADA |
| RNF-06 | Contratos | Todas las 35 operaciones declaradas tienen respuesta documentada y sin discrepancia material con FastAPI | Validación OpenAPI y comparación con `/openapi.json` generado |
| RNF-07 | Mantenibilidad | Dominio sin importar FastAPI, SQLAlchemy o componentes externos; controladores sin lógica crítica | Checks estáticos de dependencias y review del repositorio |
| RNF-08 | Reproducibilidad | Una base local vacía se reconstruye por migraciones y seed idempotente, con datos exclusivamente ficticios | Compose, Alembic upgrade, seed, AT-16; guía reproducible |
| RNF-09 | Seguridad de secretos | Ningún token, contraseña en claro, hash o string de conexión real aparece en logs de aplicación y repositorio | Escaneo automático, prueba de logging y revisión de configuración |
| RNF-10 | Observabilidad | Toda petición HTTP protegida ofrece `X-Request-ID` y eventos críticos son correlacionables | Pruebas de cabeceras y eventos sanitizados |
| RNF-11 | Recuperación lógica | Un fallo de adquisición incompleta/fallida nunca modifica la baseline ni se muestra como NO_CHANGES | Pruebas API/DB sobre FAILED, INCOMPLETE, NOT_COMPARABLE |
| RNF-12 | Evolucionabilidad | Fixture intercambiable detrás del puerto de fuentes, sin cambiar casos de uso de comparación | Test con adaptador alternativo en memoria y fixture fijo |
| RNF-13 | Confiabilidad local | Reiniciar el proceso FastAPI sin reinicializar volúmenes conserva información persistida | Prueba funcional tras reinicio y consulta autorizada |
| RNF-14 | Accesibilidad API | Contratos consumibles desde Swagger o cliente HTTP, incluidos ejemplos de errores y restricciones | OpenAPI validado y pruebas de integración |

## Restricciones de calidad

- La calidad no se demuestra exclusivamente con cobertura de líneas. Exigir aserciones significativas de seguridad, estados, aislamiento y atomicidad.
- Registrar versiones exactas de Python, FastAPI, SQLAlchemy, PostgreSQL y Alembic utilizadas al desarrollar; las dependencias tendrán límites/versiones fijadas mediante lock.
- `ruff` y analizador de tipos en CI; `pytest` con pruebas unitarias e integración sobre PostgreSQL (no SQLite para probar FKs y triggers PostgreSQL).
- Métricas de latencia, capacidad, volumen objetivo, SLA, RTO/RPO y requisitos de alta disponibilidad de **producción** no están validados. No asignar cifras ficticias. Durante la demo registrar tiempos de las 18 AT y errores; definir objetivos de rendimiento cuando exista carga justificable.
- Gestión de dependencias, control de credenciales, revisión de vulnerabilidades y licencia de dependencias como controles de pipeline proporcionales al prototipo.
- No afirmar certificación ISO/ASVS ni cumplimiento jurídico productivo.

## Definition of Done por caso de uso

Contrato OpenAPI actualizado; servicio de aplicación con dominio desacoplado; autorización y filtros por recurso; validaciones; transacción consistente; auditoría; prueba positiva y negativa; integración PostgreSQL cuando aplique; README operativo; trazabilidad RF→AT→test; sin datos reales/secretos.
